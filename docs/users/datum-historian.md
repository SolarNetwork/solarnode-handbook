# Datum Historian

SolarNode includes support for preserving a history of the [datum](./datum.md) generated by [Datum
Sources](./datum-sources/index.md). This history can be used by [expressions][dh-expr], for example.
Another use case is to support site-local applications that want to visualize the data collected by
SolarNode, such as a factory HMI device. For that scenario, the [datum REST API][rest-datum] can be
used by the HMI to access the datum history, using the same SolarQuery API used to access datum from
the SolarNetwork cloud.

## Default Historian

The default historian in SolarNode maintains only the 5 most recent datum generated per source ID,
since SolarNode started (it does not preserve the histor across application restarts). The default
historian **does not support** the [datum REST API][rest-datum],
however. Deploy the [Database historian](#database-historian) if you need that support.

## Database Historian

The **JDBC Datum Historian** plugin supports preserving datum in a Postgres database, limited only
by the storage constraints of the Postgres cluster. The Postgres cluster can be the same cluster
SolarNode uses for its internal database, or an external cluster hosted anywhere SolarNode can
connect to.

!!! info

	The Database Historian  is provided by the [JDBC Datum Historian][jdbc-dh] plugin, which is provided by the
	[`solarnode-app-datumhistorian-jdbc`][solarnode-app-datumhistorian-jdbc]
	[package](./setup-app/system/packages.md) in SolarNodeOS.
